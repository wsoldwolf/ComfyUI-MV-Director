# Scene振付・ユーザーEMD統合の実装順

2026-09-23。対象は開発ブランチの次期EMD/Planner経路。設計根拠は[再設計レポート](../research/scene-choreography-architecture-redesign-2026-09-23.md)。既存の生成結果と未コミット変更は保持する。

| 順序 | 作業 | 完了条件 |
|---|---|---|
| 1 | EMDの共通本文解析とDirectionでのユーザー優先 | 既存ソケットからの明示指定が該当profile本文を置換し、他項目を残す。候補は全曲promptへ入らない |
| 2 | Shotの用途別ディレクティブとCompilerの英訳・直列化 | 演技・演出・Cameraを区別し、内部ラベルはH3 promptへ出さず、日本語原文を保持する |
| 3 | PlannerのScene単位経路 | 原歌詞と作者の固定条件を各担当へ渡す。出来事→Scene演技→撮影の原文を保存し、未指定項目だけ生成する。前Sceneの採用終端を使う |
| 4 | 統合・検証 | 全手書き／部分手書き／全自動、Profile上書き、cache・再編集、歌詞候補の不採用をCPU試験で確認する。8Bは短いSceneで比較し、最終H3での再現は別判定にする |

## 2026-09-23の実行状態

1～3はオプトイン経路として実装し、旧経路を維持した。4のCPU契約試験と
実8B Scene 5・9の第一次試験は実行した。形式は成立したが振付・歌詞対象の
発現時刻は不合格なので、全曲とH3へは進めていない。証跡と次の品質ゲートは
[第一次判定](../research/scene-author-pilot-2026-09-23.md)に記録した。
Scene単位の途中再開cacheと、編集箇所に依存した部分失効は未実装であり、
現行cacheはPlanner全体の成功結果単位のままである。

仕様変更は次期系列として管理する。実装・試験中はbranchとリリースタグを作らず、リリース判断時に既存の[バージョン規約](versioning-and-releases.md)を適用する。必要なcache algorithm IDと内部schemaは採用した経路に合わせて更新する。
