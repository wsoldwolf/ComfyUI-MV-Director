# 演出候補が採用される条件

`# 演出候補`は、全Sceneへ必ず実行させる命令ではなく、Plannerが局所的に採用・発展・不採用を判断する着想リストです。現在のGemma4 31B構成では、Pythonが名詞一致や点数で候補を選ぶのではなく、Event → Performance → Cameraの各LLM担当が判断します。

## 入力と受渡し

Direction Enhancerの`user_request`へ記述します。

```markdown
# 共通プロンプト
* シーン全編を通して月明かりの夜。

# 演出候補
* 苔が題材となる場面では、道脇の大樹と根元の苔を同じ場所として確立する。人物が木へ寄り、根元の苔を指先で一度撫で、手を離して余韻を表情に残す。
```

最大12件、各本文500文字です。Enhancerは構文として候補を分離し、原文と順序をDirection artifactへ保持します。候補を共通Directionの生成本文へ混ぜず、Plannerの各担当へ一覧として渡します。Pythonによる事前の意味的な絞り込みはありません。

候補原文をCompilerやH3の全Scene共通prefixへ直接複製する経路ではありません。候補を参考に生成された完成EMDの演出・演技・Cameraが、Compilerを経てH3へ渡ります。

## 担当ごとの採用条件

| 担当 | 候補を使う条件 |
|---|---|
| Event：対象・出来事 | 現在Shotの原歌詞の対象・文意とSceneの状況に合う。採用する場合は対象・場所・可視変化の関係を保つ |
| Performance：人物演技 | 現在の歌詞・感情と、採用済みの出来事に両立する身体動作として使える |
| Camera：撮影 | 採用済みの演技と歌唱区間を見せる局所的な撮影意図として使える |

前後の歌詞sectionは意味と感情を理解する文脈です。そこにある全対象を今回Sceneへ出す指示ではありません。背景Visionの設備一覧も、人物が触れる対象を自動選択する命令ではありません。

音声活動付きTemplateでは、歌声のないイントロ・間奏も候補を検討する場面です。Performanceへは現在Sceneのボーカル不在候補と前後有声境界を渡し、歌詞のないSceneには近接する前後歌詞を少量だけ読み取り文脈として渡します。例えば「伴奏が続く場面で重心を移し、胸郭から腕へ弧を渡す」といった身体候補を置けます。ただし全Sceneへの自動挿入ではなく、活動検出から音楽の拍や強弱を推定する機能でもありません。短い息継ぎ、判定保留、H3用の追加paddingも別の新演出へ一律に置き換えません。

一件の候補に対象・人物動作・撮影を併記しても、三担当はそれぞれの責務として扱います。一件全体が不可分に選択され、そのまま挿入される契約ではありません。Eventが候補を採用しなくても、Performanceが身体動作部分を参考にすることは可能です。ただし、Camera担当が候補から新しい対象や人物動作を追加することは求めていません。

## UIの優先度

Plannerの`staging_candidate_policy`を切り替えます。

- `optional`（既定）：任意の着想として扱います。
- `prefer_matched`：現在Shotの原歌詞に適合する作者候補を、背景や前Sceneからの独自案より優先して検討するようEvent担当へ指示します。

`prefer_matched`も強制採用ではありません。候補が合わないShotでは独自案や「なし」を選べます。数値的な採用率や確率を指定するパラメータでもありません。PerformanceとCameraも同じpolicy値を受け取りますが、現行シスプロでこの優先順位を明示しているのはEvent担当です。

## 保証されないことと作者の確定指示

歌詞に「苔」があるだけで、苔の候補が必ず採用される保証はありません。名詞の文字列一致ではなく、LLMが文意と場面を判断します。候補が出なかったことを理由とする必須採用チェック、意味監査、強制挿入、リトライはありません。プロトコル欠落等の有限回復とは別です。

採用状況は完成EMDの`演出`、`演技`、`カメラ`を確認し、必要ならPlannerの`save_debug_output`で要求payloadと応答を追います。現在、候補ごとの統一された「採用／不採用と理由」の一覧は出力しません。

必ずそのShotに入れたい内容は、作者EMDの該当Shotへ`演出`、`演技`、`カメラ`として直接記述する方法があります。そのfieldは固定され、LLMによる生成を省略します。ただし、プロンプトに記述した内容がH3映像で完全に再現される保証とは異なります。

## モーション補完との違い

`# 演出候補`と`# モーション補完`は別機能です。

- 演出候補：LLMが局所的に参考にする任意の着想。Pythonは候補を選んで挿入しません。
- モーション補完：ユーザー又はprofileのテンプレートを、適格なShotへ明示的に別行で合成します。初期選択はScene番号による巡回で、対応profileでは生成結果を見てLLMが既存テンプレートを選び直します。

単一人物、作者演技や一般本文の有無、未固定Camera、4秒以上などはモーション補完の適格条件です。演出候補の採用条件へ読み替えないでください。

厳密な入力契約は[EMD仕様](../spec/emd-spec.md#計画入力だけで使う演出候補ディレクティブ)、UIと補完の詳細は[Plannerマニュアル](../nodes/timeline-planner.md#演出候補と補完)を参照してください。
