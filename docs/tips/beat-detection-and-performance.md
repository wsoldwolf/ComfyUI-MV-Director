# ビート検出と身体演技の間にある隔たり

フルミックスからビートを検出し、その時刻をLLMの演技生成へ渡す実験では、映像で認識できるリズム感や振付の改善は確認できなかった。拍の位置が分かることと、その拍で人物が何をするかを決めることは別の問題だった。

現時点の考察は、**拍単位の情報はLLMやH3へ渡す演技指示として粒度が細かく、具体的な身体動作を想起させる意味が不足していた可能性がある**、というもの。検出自体が無意味だった、又はLLMやH3が時間情報を一切扱えない、という結論ではない。本稿は2026年10月3〜4日の短区間検証をまとめたTIPSであり、正式なEMD仕様やビート同期機能の説明ではない。

## 実験で確認できたこと

「千里の秋を駆ける」Momiji2版のフルミックスをlibrosaで解析した。全曲の自動推定は約112 BPMだったが、作者によるクリック音の比較では167 BPM候補の方が伴奏に合うと評価された。167 BPM候補は作者の判断に基づく指定値であり、自動検出で正解BPMを確定したわけではない。

約10秒の間奏Sceneでは、28個の拍候補を6拍ごとに間引き、約1.1、3.3、5.4、7.6、9.7秒という五つの節目をGemma4 31Bへ渡した。参考情報として渡すだけでは、生成本文から採用の有無を判定できなかった。節目を選んで時間の目安を書く追加指示を与えると、「約3秒で胸郭と腕を開き、約5秒で緊張を解放する」という本文になった。

通常のCompilerによる英訳でも約3秒・約5秒の意味は残り、単独クリップの時刻原点と音声の切り出しも照合した。それでも作者の動画評価は「映像からもビートが読み取れない。あまり効果的ではないかもしれない」だった。この方式を演技改善として採用する根拠は得られなかった。

比較は単一Scene・単一seedであり、時刻情報だけでなくLLMが生成した動作内容も異なる。したがって、細かな粒度だけが原因と確定した試験ではない。一方、時刻の伝達に成功したことを、映像での演技改善に成功したことと取り違えてはいけない。

## 時刻は振付そのものではない

ビート検出が与えるのは主に「いつ」であり、「何を」「どのように」「次へどうつなぐか」ではない。167 BPMという値や拍時刻の配列だけでは、重心移動、胸郭の捻り、腕の軌道、支持足の踏み替え、動作の溜めと解放は決まらない。拍を間引いて情報量を減らしても、この意味の隔たりは残る。

例えば「約3秒でアクセント」という指示には、人物が腕を広げるのか、胸郭を捻るのか、足を踏み替えるのかという動作が含まれていない。具体的な動作を補った場合も、一回の展開と解放だけでは、伴奏全体にわたる連続した振付にならない可能性がある。

今回の実験から考えられるのは、**身体演技の土台を先に用意し、音楽情報をその動作の節目として使う方が適しているかもしれない**という仮説である。拍情報から振付を直接生み出すことと、既存の動作を曲の流れへ寄せることは分けて設計する必要がある。

## 具体的な動作指定との比較で得られた示唆

後続の同じ間奏区間では、拍時刻を使わず、演技部分を短い「剣を右手に保持したまま踊る」という英文へ直接置換した。作者は基準版より良いと評価したが、人形が揺れているように見え、動作量は不足していた。大きな踏み替えを加えると動きは増えたものの、コミカルに見えるという評価になった。

一方、体幹の捻りと肩・骨盤の連動を指定した版は自然な演技として評価された。さらに、各踏み替えが次へつながりShot全体で踊り続ける版も改善と評価された。ただし、人物自身の回転は別の課題として残った。

これらは研究側が英語Planを直接変更した試験で、通常のLLM・Compiler経路の成功を証明するものではない。それでも、この条件では細かな拍時刻を与えるより、身体の連動と動作の継続を示す方が有用だった。短ければ常に良いのではなく、画面で読める動作を渡すことが重要である。[H3へ渡す文と映像の因果関係](compact-h3-visual-spec.md)も参照。

## 再検討するときの方針

今回のビート時刻方式を正式ノード、EMDディレクティブ、既定WFへ採用する判断は保留する。再開するなら拍数を増やすことより、身体動作と音楽の関係を粗い単位へまとめることを優先する。

- 動作は先に定義する。荷重移動から体幹、肩、腕へつながる身体フレーズを土台にする。
- 音楽情報は「溜める区間」「展開する節目」「余韻へ移る区間」などの補助として使う。ただし、この粗い形式での改善はまだ未検証である。
- BPMを下げることと、元の拍から動作の節目を間引くことを区別する。動作頻度が低くても、基礎となる脈動は曲に合っている方がよい。
- 数値やEMDが整っていることを合格条件にせず、曲に合う自然な演技として見えるかを人が音付き動画で評価する。

音声活動情報による「歌唱中／伴奏中」の識別は、このビート同期とは別の役割である。ボーカルがない区間を認識することには、リップシンク指示を区別し、伴奏用の演出を選ぶ下地としての意味がある。ビート方式で改善が出なかったことを理由に、その役割まで否定しない。

また、フルミックスが完成動画へ結合されていることと、H3がその音楽を生成条件として受け取っていることは同義ではない。自然文に「音楽に合わせて」と書くだけで、モデルへ音楽条件を追加したことにもならない。厳密な同期を再検討する場合は、プロンプトの表現とは別に入力経路を確認する必要がある。
