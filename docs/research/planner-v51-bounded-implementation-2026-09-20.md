# Planner v51 限定的な歌詞解釈の実装・実8B検証

日付: 2026-09-20

## 実装範囲

[分析レポート](prototype-8b-creative-regression-analysis-2026-09-20.md)のうち、
創作的補完の許可、独立effect、短い読解文脈と重複指示の整理を実装した。
ただし**プロトタイプ相当の演出品質を達成したとは判定しない**。
実8B試験で残った意味誤認・反復を下記へ明記する。

| 項目 | v51 |
|---|---|
| LLMの推論task | 既存六taskのまま。新規分類器・監査roundなし |
| Cueの出力 | 既存九field、既存列挙値のまま |
| プロファイル設定 | Camera metadataに任意の `lyric_interpretation=literal|bounded` |
| 既定 | metadata省略時literal、同梱anime_emotional_mvはbounded |
| 読解入力 | 前後各二行・各256文字。対象の根拠としては使用不可 |
| boundedの生成指示 | Visual Beat/Actionのみ短い専用本文を選択 |
| 構文制約 | bounded Visual Beatだけ既存field順序・列挙値・要求slotをGBNFで固定 |
| EMD／Compiler／WF接続 | 変更なし |
| cache | v51へ更新し、profile metadataもcache identityへ追加 |

対象の出所は現在歌詞又は作者本文に限定する。boundedは選択済み物理対象への
非破壊的な接触や自然な支持面の補完を許すが、それを必須にしない。
明示的な作者禁止は優先し、背景設備や過去の対象を勝手に主役にしない。
人物の身体を動かすことと、対象自身が動くことを区別する。

物体・外部effectが主役なら、大きな身体演技を加える必要はない。
顔accentの表情条件は維持する。対象名はScene内で保持し、反応Shotへ
毎回書き直す要求は除いた。Pythonは演技文を合成・言い換えしない。

### 慎重に見送ったもの

- 歌詞行ごとの新しいCue Discovery LLM。
- Cue Cardの十番目以降の出力field。
- Sceneをまたぐ出来事の所有権・複数Cueの出力形式。
- 意味品質に対する全件fail-closed化、監査10回化。
- Cameraの既存割当率、境界処理、Compilerの再設計。

前後文脈で「御神木は／ただ葉を鳴らすだけ」の意味を読みやすくするが、
前Sceneだけにある「御神木」を次Sceneで新しい引用根拠としては認めない。
区間をまたぐ同一出来事の完全な所有権管理は未実装である。

## 実8B検証

使用モデル:
`E:/ComfyUI/models/LLM/GGUF/Qwen3-8B-Abliterated/qwen3-8b-abliterated-Q4_K_M.gguf`

RTX 5090が空いていることを確認して、ローカルの本番用
`LlamaCppLifecycle`と`_LlamaPlannerBackend`で実行した。
`n_ctx=16384, max_tokens=1536, temperature=0.1, seed=1`。
各10.125秒、一人の狐巫女、夜間の神社、lip_sync=offという小規模入力。
同梱emotionalのStyle/Motion/Camera本文を使用した。
動画生成・ComfyUIキュー投入・外部API通信は行っていない。
元の全曲WFや参照画像と同じ入力ではなく、二つの歌詞だけのsmoke testである。

### 試作中に見つけて直したこと

長い既存promptへ解釈例外を追記しただけの途中版では、手の上下が残り、
`required_visible_development`欠落で両ケースとも停止した。
短縮だけでは旧七field相当の応答が出て、配置と可視展開が失われた。

そのため出力fieldをさらに増やさず、既存九fieldの構文を生成時に固定した。
最終確認では二ケースとも九fieldが揃い、Cueの構造検査とEMD生成が完了した。
構文制約は自由文の内容・名詞の意味を保証しない。

### 最終確認の結果

| 歌詞 | CueとActionの観測 | 判定 |
|---|---|---|
| 昨日の願いは苔へと還る | 対象に「願い」を選び、「願いが地面に降り注ぎ、苔の上を滑るように流れる」と出力 | **意味品質は不合格**。抽象主語を物体化している |
| 朱の空に舞う狐火へ問う | 対象「狐火」、接触禁止、外部自律。「狐火が朱色の空を横切って消えていく」 | 独立effectは成立。ただし複数Shotで同じ展開を反復 |

苔ケースは12.806秒・11推論call、狐火ケースは14.031秒・16推論call。
これはモデルロードを除く一Sceneの実測であり、5060や全曲の予測値ではない。
追加taskはないが、既存のAction／Camera修復によるcall増加は残っている。
両ケースでCameraの有限fallbackが使用されたため、`complete=yes`を
カメラ品質の合格とも解釈しない。

同じ苔ケースの入力tokenは、途中の長文版から最終版へ、
Visual Beatが5782→3080、初回Actionが7807→4191へ減った。
一方、Visual Beatは構文制約のない途中版で約1.3秒、最終版では約2.7秒であり、
短縮とgrammar追加を合わせた効果を単純な高速化とは主張できない。
出力内容も異なるため、厳密な性能比較ではない。

## 残る課題と次の評価

1. **文法上の主語ではなく、描画可能な実体を選ぶこと。**
   原文包含検査は「願い」も通す。語彙の禁止辞書で塞がず、少数の対照例又は
   既存Beat内の意味選択を比較する必要がある。
2. **出来事の開始・進行・結果を各Shotへ分配すること。**
   狐火の出現から消失までを毎Shotで繰り返す傾向が残る。
   同じ対象の持続と、同じ完結動作の再開を区別する必要がある。
3. **実8Bで花・境界をまたぐ御神木・無対象区間も比較すること。**
   今回これらはmockで転送を検証しただけで、実モデルの品質確認は未実施。
4. **全曲入力と背景参照を含めた再評価。**
   小規模な成功を、プロトタイプの表現が復元できた証拠にしない。

今回の到達点は、補完を契約違反にしていた条件の整理と、出力項目を増やさず
既存構造を安定化する土台の実装である。具体演技・反復の改善は継続評価が必要。

## 利用時の注意

ComfyUIを再起動するとjunction経由で反映される。ノード追加、再配線、
新しいUI設定は不要。`anime_emotional_mv`を選ぶとboundedが使われる。
切り戻しはCamera profileの`lyric_interpretation`を`literal`にして再起動する。
これは解釈方針の切替であり、以前のモーション本文全体を復元する操作ではない。
`LlamaGrammar`未対応環境では明示的にエラーとし、未制約へ黙って退避しない。
