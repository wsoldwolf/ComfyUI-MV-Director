# EMD 00009 歌詞Cue・Scene展開評価

日付: 2026-09-20

## 対象

- EMD: `C:\Software\ComfyUI\output\mv_director\context_loop_emd_00009.md`
- 対応Plan: `C:\Software\ComfyUI\output\mv_director\context_loop_plan_00008.txt`
- 比較対象: `context_loop_emd_00008.md`

本評価では、構造的な完走だけでなく、歌詞中の具体名詞が映像上の対象、現象、人物との関係及びScene内の変化へ展開されたかを重視する。特に `苔`、`狐火`、`花` は、この楽曲の時間感覚、神秘性及び人の生の短さを映像へ変換する主要Cueである。これらの有無は単なる装飾差ではなく、MVの説得力を左右する。

## 総評

EMD 00009は構造的には正常で、16 Scenes、52 Shots、4 CUT、12 CONTINUEを持つ。長尺Arcも15本あり、石灯籠への接触、走行及び足元接写は抑制されている。

一方、歌詞連動と人物演技は未達である。`苔へと還る`、`人は花より短く咲いて`、`狐火へ問う`、`狐火は祈り` のいずれも、対応SceneのActionに対象名、対象の確立、人物との空間関係又は可視結果が存在しない。Actionは手、肩、頭部及び身体傾斜の定型文へ収束し、EMD 00008より重複が増えた。

したがって判定は次の通りとする。

- EMD構造: 合格
- CUT / CONTINUE構造: 合格
- Camera尺とArc量: 条件付き合格
- 歌詞CueによるScene展開: 不合格
- 人物演技の多様性: 不合格
- 顔演技: 不合格
- 固定設備及び走行の抑制: 合格

## `苔` Cueの評価

Scene 3は `石段に積もる`、`名もなき季節`、`昨日の願いは`、`苔へと還る`、`幼い手で結んだ` を含む。しかし採用Actionは次の三つである。

1. 手を下げ、左足を踏み出して前傾する。
2. 手を腰から引き上げ、反対の手を胸前で広げる。
3. 肩の高低差を作り、身体を傾けて沈み込む。

苔、大樹、御神木の根元、石段の表面、湿った質感、接近、視線、指先の接触又は触れた後の感情反応がない。歌詞固有のSceneではなく、他Sceneと交換可能な身体テンプレートになっている。

求める展開は、単に全Shotへ `苔` を挿入することではない。例えば次のような一回限りのScene arcである。

1. 大樹又は御神木の根元に這う苔を環境内へ確立する。
2. 人物が苔を認識し、身体の向き、視線及び距離を変える。
3. 歌詞と演出意図が接触を許す場合だけ、指先で苔を撫でて質感変化を見せる。
4. 触覚又は記憶に対する目、眉、口、肩及び呼吸の反応を見せる。
5. 手を離す、視線を残す又は立ち上がることでScene内に解放を作る。

この展開は `苔` を含むScene内で完結させ、後続Sceneへ常態化させない。

## `狐火` Cueの評価

Scene 9の `朱の空に舞う / 狐火へ問う` とScene 14の `狐火は祈り` の双方で、Actionに狐火が存在しない。人物は胸前で手を広げる、肩を上下する又は頭部を向けるだけであり、歌詞を別の文章へ交換しても成立してしまう。

狐火は人物が手に持つ道具ではなく、人物から独立した外部effectとして扱う必要がある。望ましいScene展開は次の通りである。

1. 狐火が前景、人物の側面、樹木間又は鳥居奥に出現する。
2. 狐火が人物の周囲を横切る、Arc状に周回する又は奥行き方向へ離れる。
3. 人物は手で生成、保持又は操作せず、視線、後退、振り返り、身体の開閉又は一回の手の反応を返す。
4. 光が顔、袖又は周囲の樹木を一時的に照らし、空間上の可視結果を作る。
5. 狐火が散る、遠ざかる又は祈りの方向へ集まり、Scene内で解放する。

同じ楽曲内で `狐火` が二回現れる場合も、Scene 9を「問い」、Scene 14を「祈り又は受容」として異なる意味と軌道へ分ける必要がある。人物が毎回火を手に持つ表現や、全後続Sceneへ狐火を残す表現は避ける。

## `花` Cueの評価

Scene 4には `人は花より / 短く咲いて` があるが、花又は花びらの確立、開花と散花、人物の寿命との対比及び人物反応がない。肩、腰、手及び傾斜だけで処理されている。

`花` は必ず手で摘む対象にする必要はない。むしろ次のいずれかを歌詞に応じて選択する。

- 一輪又は少数の花を環境内に確立し、短い開花又は散花を人物の時間感覚と対比する。
- 前景の花びらが人物とCameraの間を横切り、顔又は全身の感情転換を導く。
- 人物が花へ視線を落とし、短い笑み、伏し目、手を伸ばしかけて止める動作又は去る動作を返す。
- 接触を選ぶ場合も一回だけとし、保持物として後続Sceneへ持ち越さない。

ここでも重要なのは、名詞を小道具として羅列することではなく、対象の確立、人物との関係、可視変化、感情反応及び解放をScene内で作ることである。

## 顔演技

明示的な顔演技は、冒頭の閉眼と瞬き、及び二回完全一致する片目閉眼だけである。半開き、伏し目、細めた視線、視線の再接続、眉の変化及び歌唱口の感情差がActionにない。

また、`目を閉じ、瞬きを繰り返す` は状態として曖昧である。閉眼から再開眼へ移る、二回瞬きの後に視線を結ぶ、伏し目から見上げる、という時間方向の変化へ分解した方が映像化しやすい。

CameraではScene 7に全身から頭肩へ入るArc、Scene 10に顔から全身へ抜けるArcがあり、プロトタイプに近い構造は存在する。しかし対応Actionが片目閉眼又は肩と手の定型文であるため、Camera遷移が感情転換を増幅できていない。

## Camera評価

15本のArc Shotは全て約2.9秒から5.3秒であり、長尺Arcの最低尺は満たす。Scene 7のArc-to-face及びScene 10のface-to-Arcも良い方向である。

ただし15本中13本が四種類の軌道文へ集中する。Camera全体でも52本中32本が既出文の完全重複である。被写体Actionも定型姿勢であるため、生成動画では「同じ姿勢の人物の周囲をCameraだけが回る」結果になりやすい。

Cameraの次段階ではArc本数をさらに増やすより、歌詞Cueにより選ばれた対象を前景又は中景に置き、人物、対象及び背景の三層を通過する軌道をSceneごとに変えることが重要である。

## 改善した点

- 石灯籠を接近先又は接触対象にするActionはゼロになった。
- 作者又は歌詞にない走行はゼロになった。
- 足元又は足袋だけを主題にするCameraはゼロになった。
- 全SceneをCUTにする退行はなく、12 SceneがCONTINUEである。
- 高速かつ長尺のArc Shotは維持されている。

これらは維持すべきであり、歌詞Cue改善のために再び石灯籠、歩行又は足元へ依存してはならない。

## 原因分析

共通プロンプトがPlannerへ渡っていないことが主因ではない。EMDには `anime_emotional_mv` のDirectionが含まれ、Arc量、固定設備抑制及び走行抑制も反映されている。

現在のScene-level target保持は、Cue Cardが `valid` であり、かつ具体的targetを返した場合だけ動作する。そのため次の経路が残る。

1. 8Bが `苔`、`狐火`又は`花`をCue Card targetとして選ばず、`NONE`又は無効Cueを返す。
2. target保持検査が起動しない。
3. Action生成が汎用身体テンプレートを返す。
4. 一回の品質再生成又は監査再生成でも改善しない。
5. bounded recoveryの方針により、最良候補がAS ISで採用される。

別経路として、有効Cueは作成されたが一回の再生成後もtargetを欠落し、AS IS採用された可能性もある。実行ログの `Cue Card validation`、`Action quality retry`、`Action audit` により両者を区別できる。

Action反復についても、完全一致又は限られた表層類似度だけでは、左右、方向、手の位置及び肩の高低を変えた同一演技familyを十分に検出できない。さらに一回のretry後は残存違反を警告として採用するため、別の定型文familyへ収束し得る。

## Compiler翻訳上の別問題

対応Planでは共通Directionの英訳に意味反転がある。

- `目は常に全開の同じ笑顔へ固定せず` が `Keep the eyes fixed in the same smile that is fully open` になっている。
- `持つ、掴む、撫でる、触る又は動かす演技を加えず` が `perform actions such as holding, grasping, stroking, touching, or moving` になっている。
- 足袋と下駄の英訳も断片化している。

この問題はEMDのAction欠落とは別であるが、正しいEMDを作っても最終H3 promptで制約を逆転させる。歌詞Cue改善と並行して修正する必要がある。

## 次の最小改修案

### 1. Scene Cue MapをActionより先に確定する

同じLLMへ全Sceneの歌詞を短い行指向protocolで渡し、各Sceneについて次をAS ISで返させる。

- exact lyric span
- target
- target kind: object / environment / external_effect / symbolic_motif / none
- relation: observe / approach / contact / avoid / follow / release / transformation
- agency: subject / environment / independent_effect
- one-Scene scope

Pythonはtargetが元歌詞に存在すること、fieldの有限値及びScene番号だけを検証し、自然文を生成又は書換えない。

### 2. 明示名詞を`NONE`にした場合はCue段階を再要求する

Action生成後に欠落を直すのでは遅い。元歌詞に具体名詞があるSceneでCue Cardが`NONE`を返した場合、まずCue Cardだけを一回再要求する。少なくとも本楽曲の `苔`、`狐火`、`花` はCue Mapの評価用必須例とする。

この規則をPythonの語彙リストへ固定するのではなく、LLMに `SOURCE_TOKEN` を引用させ、Pythonは引用tokenが元歌詞のsubstringであることだけを検証する。これにより対象語彙を無限に列挙せずAS IS原則を維持できる。

### 3. Scene Performance Spineを一度だけ生成する

各Shotを独立生成する前に、Scene単位で次の短い骨格をLLMに作らせる。

- SETUP: 対象又は現象の確立
- RELATION: 人物が対象を認識し距離又は姿勢を変える
- EVENT: 接触、変化又は外部effectの運動
- REACTION: 顔と全身の感情反応
- RELEASE: 異なる終端姿勢又は対象の離脱

各Shot Actionはこの骨格の担当段階を受け取る。Pythonは文章を合成せず、Scene内にtargetを含むActionが最低一つ存在することと、同じ段階だけを全Shotが繰り返していないことを有限値で検証する。

### 4. 歌詞CueのScene外漏洩を監査する

対象が選択されたSceneではtargetを最低一回保持し、選択されていない後続Sceneでは接触又は操作を反復しない。`苔`は一Sceneで完結させ、`狐火`は歌詞中の二回を異なる意味へ分け、`花`はScene 4だけの比較表現として扱う。

### 5. Action familyを有限分類して反復を監査する

LLMにAction本文と共に有限な`ACTION_FAMILY`を返させる。例として `gaze_shift`、`turn_and_recoil`、`reach_and_withdraw`、`kneel_and_rise`、`effect_reaction`、`face_expression_change` 等を用いる。同じfamilyと同じ終端silhouetteの連続又は過剰使用だけを再要求し、本文は書換えない。

### 6. Compilerの否定反転を独立修正する

共通プロファイルは毎回自由翻訳させず、検証済み英語profile又は否定・保護spanを保つ翻訳経路を使用する。少なくとも `do not` を含む制約、足袋、下駄、単一人物、単一frame及び外部effectのagencyは回帰テスト対象にする。

## 合格条件

次回EMDは少なくとも次を満たすこと。

1. `苔へと還る` のSceneで、最低一つのAction又は独立した現象記述に `苔` が存在する。
2. 苔は大樹、御神木の根元、石段等のScene内位置へ確立され、人物との距離、視線、接触可否及び反応のいずれかが可視である。
3. `狐火へ問う` と `狐火は祈り` の双方で狐火が外部effectとして存在し、二Sceneの展開が同一でない。
4. 狐火を人物が持つ、生成する又は繰り返し操作するActionがない。
5. `人は花より短く咲いて` のSceneで、花又は花びらによる時間的変化と人物反応がある。
6. 苔、狐火及び花は、対応しない後続Sceneへ理由なく反復しない。
7. 石灯籠への接触、作者未指定の走行及び足元接写は引き続きゼロである。
8. 顔roleでは瞼、視線、眉、口又は表情の時間変化がActionに含まれる。
9. 同一Action文の完全重複を大幅に減らし、同一Action familyがSceneを跨いで支配しない。
10. H3へ渡る英語promptで否定条件と外部effectのagencyが反転していない。

## 必要な診断ログ

次回実行では、品質判定を可能にするため次をINFOへ残す。

- SceneごとのCue target、kind、relation及びagency
- Cue Cardの初回失敗理由とretry結果
- target保持を担当するAction slot
- Scene Performance Spineの有限段階割当
- Action quality retry理由
- auditの最終reason code
- bounded recovery後にAS IS採用したslotと残存違反

## 実装結果: Planner v46

本評価を受け、`anime_emotional_mv` camera profileへ次のmetadataを追加した。

```markdown
* `priority_lyric_cues` 苔:object,花:symbolic_motif,狐火:external_effect
```

このmetadataはUI項目を増やさずprofile選択と連動する。設定tokenが現在Sceneの
歌詞又は作者本文に完全一致する場合だけ起動し、歌詞に無いSceneへ対象を
出現させない。

- Visual Beatへ正確なtoken、kind及び根拠行を渡す。
- Cue Cardが優先tokenを主対象にしない場合、そのSceneだけを一回再要求する。
- `狐火`は`接触=禁止`かつ`現象=外部自律`を有限検証する。
- Cue Card再要求も失敗した場合、無効なCue Card本文は隔離したまま、元歌詞で
  検証済みの優先tokenをAction保持検査へ渡す。
- Shot数に応じて`establish`、`relation`、`reaction`、`release`又は複合位相を
  Actionへ割り当て、一Scene内に対象の確立、人物との関係、反応及び解放を作る。
- Scene内の最低一Actionへ正確な優先tokenを要求するが、全Shotへの対象名反復は
  要求しない。
- Action Auditは優先token欠落、位相欠落及び外部effectを人物が操作する候補を
  `MISSING_GROUNDED_CUE`としてrejectする。
- INFOログは`priority=sceneN:TOKEN/KIND`とCue Card retry対象を記録する。

Pythonは歌詞tokenの完全一致、有限kind、Cue Card列挙値及びScene位相だけを検証し、
Action自然文を生成、補完又は書換えない。採用Action本文は従来通りLLM出力を
AS ISで使用する。

## 結論

EMD 00009は、Cameraを動かす基盤、CUT / CONTINUE及び不要な固定設備の抑制には成功した。しかしMVの説得力を作る歌詞固有の視覚因果が欠けている。`苔`、`狐火`、`花`をScene内の対象又は現象として確立し、人物との関係、変化、反応及び解放へ展開することを次の最優先課題とする。
