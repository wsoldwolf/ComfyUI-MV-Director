# 旧8Bの三要素を現行映像へ統合した後の改善計画

2026-09-23。対象は`dev`のScene author実験経路と、現行の歌詞・Motion・Camera・H3連携。これは**改善計画**であり、新しい8B推論、動画生成、本番経路の変更はまだ行っていない。前回のP1b用ツール・プロンプト・証拠は未コミットの実験変更として保持する。

## 結論

旧8Bの仕組みを一から取り戻す段階ではない。現行プロジェクトでも、①Sceneの歌詞とセクション文脈、②Qwenの非thinking生成開始、③明示的な全身モーション補完をPlannerからEMD・Camera・H3へ運べるようになった。特に補完を別の`演技`行として最終EMDへ残し、Cameraへ合成後の演技を渡す経路は、旧版の「先行動作が最終出力に到達する」という利点に近い。実映像にも身体移動や外部effectの改善が現れており、この前進を取り消すべきではない。

しかし、**三要素が存在することと、それらが同じSceneの一回の演技に統合されることは別**である。ユーザーの観察では、大樹の根元の苔や旋回する狐火が改善した主要な手掛かりは、ユーザー定義の`# 演出候補`から外部注入された着想である。寄与率は対照試験前なので未確定だが、これを8Bの自発生成だけの成果と呼ばない。現行補完は適格な最長ShotへScene番号で巡回配置される。歌詞上の転換点、人物の開始・主動作・余韻、Cameraの到達構図から選ばれるわけではない。LLMは補完予定を知るが、補完原文を自分の文に再演したり、静止と大移動を競合させたりする。全16 Sceneの試験では、前Sceneの終端を渡すと動作文が反復し、外すと歩行・背景の一般物へ流れた。P1bの歌詞焦点の明示だけでも、花・御神木を選べなかった。したがって次は**旧コードの再移植でもP1bの指示追加でもなく、ユーザーの着想と身体テンプレートが最終Sceneへ届く境界**を調べる。

## 現状と残る差

| 要素 | 現行で到達したこと | 未解決の結合 |
|---|---|---|
| 歌詞単位 | 当該Shotの歌詞原文・時刻、Sceneが属するセクション文脈を別に保持する。対象のSceneを特定して映像へ出せる | 旧8Bの先行動作は完結した述語やScene先頭に強く引かれた。現行でも歌詞をShotへ分けた結果、花・御神木など後半の語が背景の汎用描写に負ける。単純にセクション全文を増やしても[既往比較](section-performance-p0-p2-2026-09-23.md)では振付は戻らない |
| ユーザー定義の演出 | `# 演出候補`はEventとPerformanceへ渡り、LLMが任意に採用・発展させる。大樹の根元の苔と狐火の演出改善はこの外部着想の寄与が大きい | 現在のEvent記録は`author`か`llm`を示すが、LLMがどの候補を利用したかは区別しない。候補が全Sceneへ残ると、歌詞から離れた反復や早すぎる出現も起こり得る |
| 生成開始 | Plannerは`/no_think`を使用し、実8Bで本文を完走できる | 旧assistant prefillと同じ開始方法ではない。ただし[旧8B再現実験](legacy-action-replay-2026-09-23.md)ではprefillと`/no_think`の両方で応答が完了し、開始方式だけで演技品質は改善しなかった。優先度は低い |
| 身体補完 | 作者／profileの`# モーション補完`を一Scene一Shotへ明示的に合成し、原LLM文と出所を分けてEMDへ保存する。Cameraは合成後の演技を読む | 選択はScene番号の巡回、配置は4秒以上の最長Shotであり、歌詞・動作・Cameraの強調点ではない。補完とLLM文の時間順や終端が不明瞭で、後続Sceneへ同じ動作が再演され得る |
| 撮影と尺 | Cameraは確定したEventと演技を参照する。継続SceneやArcも使える | 旧映像の比較的長いShotでは、身体・対象・Cameraの変化が一つの流れに収まった。現行の細かいShotでは、各Shotの開始で演技を再準備しやすい。Arcの本数を増やすだけでは解決しない |

根拠：[旧8B／27Bと現行の構成比較](japanese2json-prompt-generation-comparison-2026-09-21.md)、[明示モーション合成試験](motion-composition-2026-09-23.md)、[全16 SceneとP1bの結果](scene-composition-full-sequence-review-2026-09-23.md)。旧8B動画と復旧EMDの同一生成系列、当時のGGUF・llama.cpp・実効seedは未確定であり、旧版との差の全量をPlannerへ帰属しない。

ここで二種類の外部注入を混同しない。`# 演出候補`はLLMへの**任意の着想**であり、原文がそのまま採用される保証はない。`# モーション補完`は作者／profileの**許可済み原文を構造的に選んで別行へ合成**する。旧Pythonの固定motion追加をAS ISとの境界を明示して再現しやすいのは後者である。前者は苔の場所や狐火の軌道のような創作的な関係を導く。両方とも「外から作者の情報を渡す」という大枠では旧プロトタイプと通じるが、採用の保証と出典の扱いは異なる。

## 改善仮説の優先順位

1. **外部着想の採用と時間上の結合が主因候補。** 旧8Bの強い表現は、手書きbrief、先行動作の最終採用、Scene内の時間順配置、長めの撮影経路が組になっていた。現行の苔・狐火も外部着想で改善した。今は候補を使ったかどうか、どのShotで補完と重なったか、Cameraがそこを撮ったかを分けて追えるようにする。
2. **歌詞対象の選択が次点。** P1bでは入力に`current_lyric_focus`を重ねても背景の紅葉・鳥居がEventを占有した。候補がある場合の採用と、候補がない場合の自発生成を区別し、選んだ歌詞の原文・時刻とSceneでの一回の変化を照合する。ただし苔・花・狐火だけを特別扱いしない。
3. **生成開始方式は品質の主因とは見ない。** 空thinkingでtokenを使い切る障害は解消済み。prefillへの全面移行は、同じ入力・seed・補完で身体フレーズの明確な改善を示した場合だけ検討する。

## 実行順と停止条件

### P0：保存物だけで出典と時間を追う（GPU不要）

現在の採用Plan・EMD・H3 JSON・完成動画から、苔→花の連続区間と狐火の一区間を選ぶ。各Shotについて、歌詞原文と時刻、**ユーザー演出候補の原文と採否が追える証拠**、選択Event、8Bの素の`演技`、モーション補完の出所と配置、合成後にCameraが読んだ文、Camera軌道、H3へ届いた英文、映像上の開始／主動作／終端を一列に照合する。人物参照・背景参照とH3モデル／seedも記録する。候補とLLM出力の文面が似ていても、明示的な選択記録がなければ「候補由来と整合する」に留める。旧8B動画では同じ欄を埋められる範囲だけ復元し、欠落欄を推測で埋めない。

ここで「素の演技が弱い」「補完後に矛盾する」「Cameraが主動作を撮っていない」「H3が明示動作を表現しない」を分ける。P1bのEvent失敗と、旧方式の強い全身移動を一つの原因にまとめない。

### P1：同一素材・同一8Bで一要素ずつEMD比較（動画なし）

P0で選んだ二つの短区間だけを固定fixtureにする。Scene番号、原歌詞と時刻、作者固定文、人物・背景、モデル設定、実効seed、Shot境界は維持する。保存済み出力を対照として再利用し、必要な新規呼出しだけ行う。

1. **演出候補の寄与：** 同じ歌詞・seed・Event/Performance契約で、ユーザーの候補あり／候補なしを短区間だけ比較する。候補なしで大樹の苔・狐火が消えるなら、その効果を8Bの自発生成と呼ばない。候補ありでも区間外へ漏れるなら採用範囲の問題として分ける。結果から別の自然文をPythonで作らない。
2. **歌詞の読解単位：** 当該Shotの時刻付き原文を変えずに、同じScene内の完結した歌詞句を「意味解釈用」として演技担当へ与える場合を比較する。元歌詞を別Shotへ移さない。候補の有無と歌詞句の効果を混同しないため、同一候補条件の中だけで比較する。
3. **補完の時間配置：** 2で得た8B演技原文を固定し、補完なし／現行の最長Shot配置／演技のアクセントを選んだShotでの配置を比較する。後者は初回は手動指定のオフライン対照とし、Pythonが歌詞名詞から自然文やShotを推測する本番規則にはしない。これにより、旧Python注入に相当する直接合成の寄与と、Scene番号巡回の不適切さを分ける。合成前後の文が「準備→主動作→余韻」として読めるか、同じ動作が次Sceneに再演されないかを見る。
4. **生成開始：** 1〜3でなお8B原文そのものがボトルネックの場合に限り、同一入力で`/no_think`と旧prefillを少数比較する。完走率、出力token、身体の進行を別々に記録し、速さだけを品質としない。

P1の人手評価は、対象の可視化、身体の支持・体幹・腕・顔の時間順変化、補完との矛盾、反復、作者指示の保持を別々に採点する。語数・動詞数・Arc本数だけでは合格にしない。二短区間で改善が見えなければ全曲試験に進まず、入力・出力の出典を再診断する。

### Shot接続器の設計案：Codexが作る構造、LLMと作者が作る内容

LLMに共通資料・全候補・全Shotの前後状態を一度に投入し、Shotごとの文章まで全て推論させる必要はない。既存TemplateはScene／Shot境界、時刻、歌詞、`継続`、作者固定の`演出`・`演技`・`カメラ`を既に持つ。Codexの役割は、これを利用して**Scene内の位相を隣接Shotへ結ぶ実行時の構造的接続器**を設計・実装・試験することである。ComfyUI実行時にCodex APIを必須にする意味ではない。

| 創作側が決めること | Shot接続器が決めること |
|---|---|
| 作者の固定文、任意の演出候補・モーション候補。LLMが採用する歌詞上の出来事とその原文、Scene全体の身体フレーズ、撮影したい主動作と表情。必要なら出来事の歌詞行又は「準備／主動作／解放」という少数の位相名 | 固定済み時刻とShotへの位相の単調な割当、前Shot終端から次Shot始端への参照、候補原文の一回だけの配置、CUT／継続境界、作者固定欄の保護、Cameraが見せる位相と対象の参照関係 |

接続器は名詞から動詞を作らず、8B文を正規表現で分解・修復しない。時間順が必要なら、作者又はLLMが出した**短い位相別原文**を受け取り、その参照IDと順序をShotへ割り当てる。Shot数と位相数が違っても、同じ準備文を毎Shotへ複写する規則にはしない。継続中の位相は内部参照で保持し、最終EMD／Compilerへどう表すかは小範囲の仕様試験で決める。現行EMDに表現できない関係を、曖昧な散文で黙って補わない。

接続の最小不変条件は、①時刻と歌詞所属を変えない、②位相は前へ進み同じ主動作を再開始しない、③明示CUTをまたいで姿勢・Camera軌道を無条件継承しない、④継続Sceneでは直前の採用終端を起点にする、⑤作者固定Shotを上書きしない、⑥モーション補完原文と出所を一度だけ記録する、である。Cameraは採用済み位相の支持・手元・表情とEvent位置を参照し、Cameraの開始・見せ場・終点を接続する。Arcの方向を途中で反転させるかどうかも軌道の構造として検査できるが、Arcを選ぶ創作判断そのものは固定しない。

曖昧さは残る。例えば歌詞句が二Shotにまたがり、主動作の発生位置を一意に決められなければ、接続器が内容から勝手に意味判断しない。作者の指定を優先し、それもなければLLMへ**その一箇所だけ**選択を求めるか、配置を保留して比較実験の失敗として示す。これなら8Bへ全Shotの履歴・候補を再投入せず、追加推論も例外的かつ有界にできる。

まずP1の保存済み原文を使い、同じEvent・身体位相・Camera意図を「現行Shot別生成」と「手動で正解位置を与えた接続器の試作」の二条件へ通す。後者でもEMD上の動きが改善しなければ、接続器を本番へ導入しない。改善した場合のみ、手動位置をどこまで時刻・歌詞・作者指定から構造的に求められるかをCPU試験で縮めていく。

### P2：効果があった境界だけを現行Scene経路へ入れる

演出候補の寄与が確認できた場合は、候補を「8Bが自動生成したEvent」と混ぜず、入力由来と選択状態を記録する。候補を全Sceneの共通命令にせず、LLMが当該歌詞・Sceneで採用又は不採用を決められる形を試す。歌詞の読解単位が効いた場合は、当該Scene原文・時刻と、意味解釈用の完結句を分けて渡す。補完配置とShot接続が効いた場合は、LLM又は作者がモーションテンプレートIDとScene内の身体位相を決め、接続器が固定済み時刻・歌詞・作者Shot条件へ割り当てる。曖昧な位置だけを局所選択に戻す。PythonはID・Shot範囲と作者優先を検証して、作者／profileの**原文だけ**を合成する。候補の不採用も許す。別の監査LLMや物体名辞書、出力後の自然文修復は初手で追加しない。

Cameraには採用済みの8B演技原文と補完、Event、アクセントの位置を渡す。全身→表情、Arc→顔、接触→解放を同じSceneの時間軸として撮れるかを確かめる。作者固定の`演技`・`カメラ`・継続、任意の`# 演出候補`、明示的な`# モーション補完`の優先順位を守る。新しい輸送フィールドが必要な場合は実験用profileだけに置き、cache識別・仕様・CPU試験を同時更新する。

### P3：EMD合格後に一短区間だけH3で確認

同一の音声、人物／背景画像、H3 Hybrid Loader設定、scheduler、解像度、steps、seedで、元EMDと採用案を各一回だけレンダリングする。Scene Debug Splitterで連続した前後Sceneを含め、身体の受け渡しとCameraの到達を確認する。旧8B動画は表現目標として横に置くが、設定差があるため厳密なA/Bの点数には混ぜない。短区間で映像差がなければ全編生成を行わず、EMD→Compiler→H3 promptと動画モデルのどこで差が消えたかを調べる。

## 採用条件と避けること

採用条件は、二つの短区間で歌詞対象の発生位置が読め、身体が一つのフレーズとして進み、同じ補完の反復・静止との競合がなく、Cameraが主動作と表情を隠さないこと。構文完走だけでは不十分。CPU契約、16k contextと推論回数、5060での運用費も確認する。品質が改善しても別曲への一般化は未証明として明記する。

旧Pythonの`_motion_phase_additions`と`_apply_lyric_action_blueprint`を無条件移植しない。P1bで不合格だった歌詞焦点を長い禁止文でさらに囲まない。全編レンダリング、seed総当たり、新たな全曲LLM段、強制的なArc増量はP0・P1の代わりにしない。旧版で得られた表現を目標にしつつ、現行ですでに映像へ届いた三要素を壊さず、**どの境界の変更が画面上の演技を増やしたか**を確かめてから採用する。
