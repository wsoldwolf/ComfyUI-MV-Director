# 原歌詞の対象とEVENT.CHANGEの直接描写：8Bオフライン検証

2026-09-22

## 結論

**「人物の手から狐火を発生させる」は、それだけでは不適合ではない。** 狐火が実際に現れ、手元で光る又は手を離れて動くなら、`TARGET=狐火`に対応する可視の出来事である。狐火の起源・自律性は表現上の選択とし、対象と出来事の一致とは別の軸で扱う。

一方、今回の採点は**「対象を同じCHANGE内で直接見せ、変化・関係を作る」狭い実験契約**であり、MVとしての良否や意味的一致全般を測っていない。Qwen3-8B-Abliteratedの判定がこの契約に一致したのは引用根拠付き形式で両軸24/32件、引用なし形式で16/32件だった。人間が解釈できる暗示・比喩・環境描写を「誤判定」や「失敗」と呼ぶのは過剰だった。この監査を本番の合否ゲートにはしない。二つのseedは独立した曲やモデルを代表しないため、この数値を一般的な精度ともみなさない。

## 評価の境界と条件

[事前ラベル付き16例](../assets/research/scene-target-event-alignment-2026-09-22/cases.json)を推論前に固定した。原歌詞・対象・`EVENT.CHANGE`の短い組を、seed 42/43で各一回判定した。対象は社、狐火、苔、花、灯籠。狐火は手起点で周囲へ広がる例、手起点で上昇する例、独立して旋回する例、腕の動作だけで狐火が現れない例、背景に静止する例を含む。社は足音だけ、灯籠への接触、`神社`への部分文字列による誤認を対照にした。

- `SOURCE=yes`: 選択した対象に**現在Sceneの原歌詞**の根拠がある。別Sceneや背景にあるだけなら`no`。
- `EVENT=yes`: この実験の**直接描写ラベル**では、`CHANGE`内で対象自身が現れる・動く・変化するか、人物の視線・接触など撮影可能な関係が起きる。対象名が別欄にあるだけ、静的な背景、足音・歩行は`no`とした。ただし、`no`はMV表現としての不適合を意味しない。
- 狐火の発生源を手にすること、独立現象にすること自体は、この二軸の採点対象にしない。
- 引用形式では`EVENT=yes`なら`CHANGE`内の連続文字列を根拠として引用し、`no`なら`なし`を要求した。引用なし形式は同じ意味基準で二値だけを返した。

モデルはQwen3-8B-Abliterated Q4_K_M、`n_ctx=16384`。実行条件と全応答は[引用付き証跡](../assets/research/scene-target-event-alignment-2026-09-22/evidence.json)と[引用なし証跡](../assets/research/scene-target-event-alignment-2026-09-22/evidence_binary.json)に保存した。有限文法で出力形だけを制約し、自然文の意味や正解ラベルをPythonで補正していない。短文の合成・対照例であり、実際の全曲EMDや動画の品質を測ったものではない。

## 結果

| 指標（16例×2 seed） | 引用付き | 引用なし |
| --- | ---: | ---: |
| 形式成立 | 32/32 | 32/32 |
| `SOURCE`の実験ラベルと一致 | 30/32 | 29/32 |
| `EVENT`の直接描写ラベルと一致 | 26/32 | 19/32 |
| 両ラベルと一致 | 24/32 | 16/32 |
| 直接描写ありを捕捉 | 16/16 | 16/16 |
| 直接描写なしを捕捉 | 10/16 | 3/16 |
| 狐火の手起点二例を適合と判定 | 4/4 | 4/4 |
| 引用欄の規約成立 | 9/32 | 対象外 |

引用付き形式では、`shrine_substring_trap`の「神社へ向かう」、`foxfire_hands_only`の腕による祈り、`foxfire_static_backdrop`の背景の狐火を両seedで`EVENT=yes`とし、厳格な直接描写ラベルとは異なった。しかし「神社へ向かう」は到達への予感、祈りの身振りは「狐火は祈り」という歌詞の比喩、背景の狐火は雰囲気として、人間には十分解釈可能である。これらを映像品質の誤りとは断定しない。苔の根元への接触、花びらの移動、狐火の手起点・独立発生は両seedで直接描写ありと判定した。歌詞に灯籠がない例の`SOURCE=no`も、灯籠の火で狐火を連想させる解釈まで排除すべき根拠にはならない。

引用欄では歌詞の文言を`CHANGE`の根拠として転記したり、`EVENT=no`なのに`CHANGE`の文を引用したりする例が多い。引用文字列の同一性を検証しても9/32件しか規約を満たさず、根拠を付けさせるだけで堅牢な直接描写判定にはならなかった。ただし引用欄を完全に省くと直接描写なしの捕捉がさらに悪化した。今回の短文では平均応答時間が引用付き約0.47秒、引用なし約0.20秒だった（モデル読込を除く）。

## 解釈と次の設計

狐火が手から生まれる、独立して旋回する、背景に存在する、あるいは祈りの身振りで暗示される、いずれもMVでは使い得る。対象を毎Sceneで直接動かす義務はない。厳格な直接描写テストは「今回の歌詞対象を視覚的に強調したいのに、実際には何を映しているか」を診断する補助指標に限定する。起源や自律性を禁止規則にすると、手元から周囲へ広がる有効な演出まで失う。

次に評価するなら、合否の二値よりも、**直接描写／解釈可能な暗示／文脈上のつながりが薄い**という段階的な人手評価を、実際のScene前後・歌詞・最終映像を見ながら行う。ショット一行だけでは前後から生まれる意味を採点できない。LLM監査は「対象が見えない可能性がある」という参考情報に留め、再生成の停止条件にしない。`EVENT.CHANGE`はLLM出力をAS ISで保持し、Pythonで意味文を修復しない。本研究では本番Planner、Compiler、プロファイル、H3を変更していない。
